# BW16 I2C 4.5 companion firmware

This optional download is for the **BW16 RTL8720DN board**, used by **Apps > GPIO > BW16 I2C** in T-Embed Azazil r3/r4. It is not T-Embed firmware and does not go on the SD card. The earlier release included the companion source but omitted a separate flashable package; this add-on supplies it without changing the r4 T-Embed BIN or SD archive.

Download **BW16-I2C-4.5-Azazil-Companion.zip** from the r4 release assets. The ZIP contains the compiled application, matching KM0/KM4 boot images, RAM flashloader, official Windows uploader, hash-checking PowerShell helper, source and build/test logs. `BW16-SHA256SUMS.txt` identifies this additional ZIP; the original SHA256SUMS.txt still covers the three original r4 artifacts.

## Flash on Windows

1. Extract the whole ZIP to a folder. Do not run it inside the ZIP.
2. Disconnect all BW16-to-T-Embed wires. Connect only the BW16 USB and find its COM port in Device Manager.
3. Open PowerShell in the extracted folder. Optional file verification without opening a port:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\FLASH_BW16.ps1 -CheckOnly
   ```

4. Enter BW16 download mode: hold **BURN**, press and release **RST**, then release **BURN**. Run, replacing COM3 with the BW16's port:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\FLASH_BW16.ps1 -Port COM3 -BaudRate 460800
   ```

5. Wait for **SUCCESS: boot and application checksums verified**. If verification fails, keep the log and do not treat the flash as successful. Press RST, then disconnect BW16 USB before reconnecting the boards.

The helper verifies all four image hashes and the uploader hash before opening the port. It uses the bundled uploader's command syntax, not the different SDK uploader syntax. **Do not use esptool or the T-Embed 0x0 instructions on the BW16.** The uploader handles the BW16 boot and application locations. Back up any previous BW16 firmware you need before replacing it.

## I2C wiring

Fully power off the T-Embed and remove its USB before connecting the BW16; deep sleep is insufficient. Identify the actual signal labels, not wire colours.

| T-Embed CC1101 Plus | BW16 |
| --- | --- |
| GPIO8 / SDA | PA26 / D8 / SDA |
| GPIO18 / SCL | PA25 / D7 / SCL |
| GND | GND |
| Stable 3.3 V supply | 3V3 |

Use 3.3 V signal pull-ups. Confirm your BW16 carrier exposes these pads. Keep GPIO43/44 available for the Plus NRF; this is **not UART firmware**. Do not connect the boards' power rails while both are USB-powered.

On the T-Embed, use `apps/GPIO/bw16_r4tkn_i2c.fap` from the existing r3/r4 SD pack. No new SD copy or T-Embed reflash is required solely for this BW16 add-on if r3/r4 is already installed. If your BW16 already runs this matching I2C 4.5 controller and connects correctly, this is a packaged rebuild, not a required feature upgrade.

## Validation and provenance

Compiled for `realtek:AmebaD:Ai-Thinker_BW16` with AmebaD **3.1.9**, ASDK toolchain **1.0.1**, and tools **1.1.3**. The SDK reports 688892 bytes (32% of its 2097152-byte program limit). The existing host harness passes interrupted/short I2C transfers, retry/deduplication, reconnect, STOP, backpressure, capture reconstruction, timeout and low-heap cases. No controller/radio behavior was changed to create this package. Physical BW16 flashing, I2C communication and radio operation remain untested for this build.

The complete matching source is in `source/` and also in the named r4 Source ZIP under `firmware/bw16_controller_i2c`, with its shared controller/link directories. Original GPL-3.0-or-later notices are retained. Realtek SDK boot images/libraries and uploader retain their respective upstream licensing.

Official uploader binary and corresponding source are from Ameba-AIoT/ameba-arduino-d commit `6626360b6f6af698bfed794ca9e396b14a44ca3c`, `Ameba_misc/Autoflash_patch/`. The uploader imports only Windows KERNEL32 and msvcrt; no separate Cygwin DLL is required for this pinned version.
